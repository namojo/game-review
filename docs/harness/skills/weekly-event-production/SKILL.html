nameweekly-event-production
description「원시인 형님들 키우기」 게임 내 주간 이벤트를 주제 선정 → 제목·본문 작성 → 키아트 생성(codex-image) → 다국어 번역 → 언어별 배너 합성 → Google Play 프로모션 콘텐츠·App Store 인앱 이벤트 등록 시트까지 한 번에 만드는 제작 절차. 주간 이벤트 기획, 이벤트 캘린더, 이벤트 문구·번역, 이벤트 배너·키아트·이미지 제작, 스토어 이벤트 등록, 이벤트 키트 수정·다시 만들기 요청 시 사용한다. 광고 소재(UA 크리에이티브) 성과 분석은 ad-performance-automation 이 맡는다.

주간 이벤트 제작 절차

지금은 매주 주제 선정, 문구, 번역, 이미지, 스토어 등록을 각각 처리한다(운영 1~2시간 + 디자인 1~2일). 이 절차는 이벤트 1건 = 키트 1개로 묶어, 운영자가 주제만 승인하면 나머지가 같은 형식으로 나오게 한다. 디자인팀은 0에서 그리지 않고 키아트를 검수하고 다듬는 역할로 바뀐다.

산출물 (이벤트 키트)

deliverables/task2-weekly-event/
├── event_calendar.md                 ← 향후 8주 주제 후보 + 선정 근거
└── {event_id}/                       ← 예: 2026-w44-halloween
    ├── event_brief.md                ← 기획서: 기간, 대상 국가, 미션·보상 구조, 인게임 공지·푸시 문구(ko)
    ├── copy.json                     ← 언어별 문구(배너·공지·푸시·스토어 필드) — 단일 진실 원천
    ├── store_submission.md           ← Play·App Store 등록 시트(필드별 글자 수 검증 포함)
    ├── keyart/                       ← 글자 없는 원본 키아트(codex-image)
    │   ├── keyart_16x9.png  keyart_9x16.png  keyart_1x1.png
    │   └── prompts.md                ← 사용한 프롬프트 전문(재생성용)
    └── localized/                    ← compose_banner.py 결과: banner_{lang}_{format}.png

절차

1. 주제 선정 (planner)

  • 입력: 오늘 날짜, 대상 국가(리뷰 언어 분포 = 실제 사용자 분포의 대리 지표: ko·pt·en·ru·id·es·th 순), 시즌 이벤트, 최근 리뷰 이슈.
  • 향후 8주 후보를 표로 만든다: 주차, 기간(월~일), 주제, 대상 국가, 근거(시즌·국가 기념일·게임 콘텐츠), 리스크(예: 특정 국가 종교·문화 민감성).
  • 리뷰 인사이트를 이벤트에 연결한다. 예: 광고 피로 불만이 많으면 "광고 없이 보상 2배 주말" 같은 이벤트가 평점 방어에 도움이 된다.
  • 이번 주 제작 대상 1건을 고르고 이유를 적는다.

2. 기획·문구 (planner)

  • event_brief.md: 이벤트명, 한 줄 콘셉트, 기간(KST와 UTC 병기), 미션 3~5개, 보상 구조, 인게임 공지 본문, 푸시 문구 2종.
  • 게임 내 실제 시스템(문명, 토템, 형님의 탑, 보스토벌, 장비 합성, 슬롯머신)과 맞춘다. 없는 시스템을 지어내지 않는다. 확실하지 않으면 "[기획 확인 필요]"로 표시한다.
  • copy.json 에 언어별로 쓴다. 용어는 references/localization-glossary.md 를 따른다. 글자 수 한도는 references/store-event-specs.md 표를 지키고, 각 필드의 실제 글자 수를 store_submission.md 에 적는다.
  • 번역은 직역하지 않는다. 각 언어 사용자가 게임 이벤트 공지에서 흔히 보는 표현으로 쓴다(현지화).

3. 키아트 (visual designer)

  • references/keyart-prompting.md 의 프롬프트 구조를 따른다. 글자 없는 이미지를 만든다.
  • 화풍 참고 이미지: _workspace/00_input/game_art/ (header.png, shot1.png, shot2.png). 게임의 웹툰풍 화풍을 유지하기 위해서다.
  • 규격 3종을 한 번에 병렬 생성한다.
.claude/skills/weekly-event-production/scripts/gen_keyart.sh \
  deliverables/task2-weekly-event/{event_id}/keyart \
  _workspace/00_input/game_art/shot1.png,_workspace/00_input/game_art/shot2.png \
  "가로형 ...::keyart_16x9.png" "세로형 ...::keyart_9x16.png" "정사각형 ...::keyart_1x1.png"
  • Bash run_in_background: true 로 실행하고 완료 알림을 기다린다. 장당 1~3분 걸린다.
  • 생성 뒤 이미지를 직접 열어 본다. 글자가 들어갔거나, 문구 자리가 비지 않았거나, 화풍이 크게 다르면 그 장만 프롬프트를 고쳐 다시 만든다(최대 2회).

4. 언어별 배너 합성 (visual designer)

./.venv/bin/python .claude/skills/weekly-event-production/scripts/compose_banner.py \
  --copy deliverables/task2-weekly-event/{event_id}/copy.json \
  --bg landscape=.../keyart/keyart_16x9.png --bg portrait=.../keyart/keyart_9x16.png \
  --bg square=.../keyart/keyart_1x1.png --outdir .../localized
  • copy.json 의 locales.{lang}.banner 객체(title, subtitle, period, badge)를 읽는다. 구조는 references/store-event-specs.md 끝의 예시를 따른다.
  • 결과를 언어별로 몇 장씩 열어 본다. 글자가 잘리거나 얼굴을 가리면 문구를 줄이거나 \n 으로 줄을 직접 나눈다.
  • 두 스토어 모두 글자 없는 키아트 원본을 제출한다. App Store 는 이벤트명을 따로 표시하고, Google Play 프로모션 콘텐츠 가이드라인은 이미지 속 글자(로고·슬로건·이벤트명)를 금지한다(2026-10 planner 확인). 합성 배너는 인게임 공지·SNS 전용이다.

4-1. 스토어 제출용 규격 사본 (visual designer)

./.venv/bin/python .claude/skills/weekly-event-production/scripts/make_store_assets.py \
  deliverables/task2-weekly-event/{event_id}/keyart     # → keyart/store/*_1920x1080 등 3장

생성 원본은 스토어 규격과 해상도가 달라 그대로 내면 반려된다. store_submission.md·copy.json 의 제출 경로는 이 사본을 가리킨다.

5. 스토어 등록 시트 (planner)

  • store_submission.md: Google Play 프로모션 콘텐츠, App Store 인앱 이벤트 필드를 언어별 표로 쓰고, 제출할 이미지 파일 경로를 적는다.
  • 자동화 가능 범위를 적는다: App Store Connect API는 인앱 이벤트 생성을 지원한다(appEvents). Google Play 프로모션 콘텐츠는 Play Console에서 등록한다. 등록 전 체크리스트(기간, 딥링크, 대상 국가, 검토 소요 기간)를 붙인다.

품질 기준

  • 같은 이벤트의 모든 산출물(배너·공지·스토어 문구)이 같은 이름과 기간을 쓴다. 단일 원천(copy.json)에서만 문구를 가져오는 이유다.
  • 기간 표기는 각 국가 관습을 따른다(ko 10.26 – 11.01, en Oct 26 – Nov 1, ru 26.10 – 01.11).
  • 보상 수치·확률을 확정해 쓰지 않는다. 실제 수치는 기획 확인 대상이다.

재실행

  • 문구만 수정: copy.json 을 고치고 4단계만 다시 실행한다(수십 초).
  • 이미지 한 장만 다시: 해당 규격만 gen_keyart.sh 로 다시 만들고 4단계를 다시 실행한다.
  • 다음 주 이벤트: event_calendar.md 에서 다음 주제를 골라 2단계부터 실행한다.

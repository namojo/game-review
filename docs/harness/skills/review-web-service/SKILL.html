namereview-web-service
description리뷰 대응 검수 웹서비스(정적 SPA)를 만들고 GitHub Pages(namojo.github.io/game-review)에 배포하는 절차. 리뷰 대시보드, 검수 인박스, 답변 승인·내보내기, Claude API 재생성(BYOK), 운영 파이프라인 코드(수집·초안·등록 스크립트, GitHub Actions), 배포·재배포·화면 수정 요청 시 사용한다. 리뷰 데이터 자체의 분류·답변 작성은 review-response-ops 스킬이 맡는다.

리뷰 대응 웹서비스 구현·배포

운영 담당자가 매일 10분 안에 리뷰를 처리하게 만드는 검수 도구다. 데모는 실제 리뷰와 AI 초안으로 동작하고, 운영 전환 때 데이터 소스만 공식 API로 바꾸면 되도록 만든다.

결과물 구조

game-review/                    ← 독립 git 저장소 (namojo/game-review)
├── index.html                  ← 빌드 없이 바로 열리는 SPA
├── assets/app.css, app.js      ← ES 모듈. 외부 라이브러리는 CDN(cdnjs/jsdelivr)만
├── data/reviews.json           ← merge_for_site.py 산출물 (계약: references/data-contract.md)
├── pipeline/                   ← 운영 전환용 코드
│   ├── fetch_reviews.py        ← review-response-ops 스크립트 복사본
│   ├── draft_replies.py        ← Claude API 분류·번역·초안 (배치, JSON 출력)
│   ├── post_replies.py         ← 승인 건을 Play/App Store API로 등록 (--dry-run 기본)
│   ├── requirements.txt
│   └── README.md
├── .github/workflows/refresh-reviews.yml   ← 수동 실행 + (주석 처리된) 매일 스케줄
├── .nojekyll
└── README.md

작업 순서

  1. references/data-contract.md 를 읽고 data/reviews.json 의 실제 필드와 대조한다. 화면 코드는 계약 문서가 아니라 실제 파일에 맞춘다. 둘이 다르면 오케스트레이터에 알린다.
  2. references/ui-spec.md 의 화면·기능을 구현한다. 시각 디자인은 frontend-design 스킬을 불러와 방향을 정한다. 게임 톤(돌·흙·불 색, 굵은 외곽선)을 은은하게 반영하되, 업무 도구이므로 가독성이 먼저다.
  3. Claude API를 호출하는 코드(브라우저 BYOK 재생성, pipeline/draft_replies.py)를 쓰기 전에 claude-api 스킬을 불러와 최신 모델 ID·요청 형식을 확인한다. 기본값: 분류·번역 claude-haiku-4-5, 맞춤 답변 claude-sonnet-5-5.
  4. 로컬에서 확인한다: python3 -m http.server -d game-review 8765 → Playwright로 첫 화면·필터·상세·승인·내보내기를 클릭해 보고 콘솔 오류 0건, 390px 폭에서 가로 스크롤이 없는지 본다.
  5. QA 통과 후 references/deploy.md 절차로 배포하고 공개 URL에서 다시 확인한다.

반드시 지킬 것 — 이유

  • API 키를 코드에 넣지 않는다. 공개 저장소·공개 사이트다. BYOK 키는 사용자가 설정 화면에서 입력하고 localStorage 에만 둔다(초기화 버튼 제공). 브라우저 직접 호출에는 anthropic-dangerous-direct-browser-access: true 헤더가 필요하다는 점과 위험(키 노출)을 설정 화면에 한 줄로 밝힌다.
  • 상대 경로만 쓴다. 사이트가 /game-review/ 하위 경로에서 서비스되므로 /data/... 같은 절대 경로는 깨진다.
  • 검수 상태는 브라우저에 저장한다(localStorage, try/catch 로 감싼다). 데모에는 서버가 없다. 운영 전환 시 DB로 옮길 지점을 코드 주석과 README에 표시한다.
  • 350자 카운터: Google Play 답변은 350자를 넘으면 등록이 거부된다. 편집 중 실시간 글자 수와 초과 경고를 보여준다.
  • 기존 답변 비교: existing_reply 가 있으면 "현재 운영 답변(템플릿)"과 "AI 초안"을 나란히 보여준다. 이 화면이 컨설팅의 핵심 근거다.
  • 개인정보: 작성자 이름은 데이터에 없다. 화면에 원 작성자 이름을 복원하거나 추측해 넣지 않는다.
  • 공식 서비스로 오인되지 않게 푸터에 "썬더게임즈 AI 전환 컨설팅 PoC — 공개 리뷰 데이터 기반, 실제 스토어에 답변을 등록하지 않음"을 표시한다.

재실행·수정 요청

  • 데이터만 갱신: review-response-ops 로 data/reviews.json 을 다시 만든 뒤 커밋·푸시만 한다. 화면 코드는 건드리지 않는다.
  • 화면 수정: 해당 부분만 고치고 4단계 확인을 다시 한 뒤 재배포한다.

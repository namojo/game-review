배포 절차 (GitHub Pages — 프로젝트 사이트)

목표 URL: https://namojo.github.io/game-review/

namojo.github.io 는 이미 사용자 사이트 저장소(namojo/namojo.github.io)가 있다. 그 저장소를 건드리지 않고, 별도 저장소 namojo/game-review 를 Pages 프로젝트 사이트로 배포하면 /game-review/ 경로로 서비스된다. 기존 사이트에 game-review/ 폴더가 있으면 경로가 충돌하므로 먼저 확인한다.

# 0) 사전 확인
gh auth status                                     # namojo 계정, repo·workflow 권한
gh api repos/namojo/namojo.github.io/contents/game-review 2>&1 | head -1   # 404 여야 충돌 없음
gh repo view namojo/game-review 2>&1 | head -1     # 없으면 새로 만든다

# 1) 저장소 초기화·첫 푸시
cd game-review
touch .nojekyll                                    # _ 로 시작하는 파일도 서비스되게
git init -b main && git add -A && git commit -m "Initial: review response PoC"
gh repo create namojo/game-review --public --source=. --remote=origin --push \
  --description "원시인 형님들 키우기 리뷰 대응 자동화 PoC (AI 전환 컨설팅)"

# 2) Pages 활성화 (main 브랜치 루트)
gh api -X POST repos/namojo/game-review/pages -f "source[branch]=main" -f "source[path]=/" \
  || gh api -X PUT repos/namojo/game-review/pages -f "source[branch]=main" -f "source[path]=/"

# 3) 배포 확인 — 첫 빌드는 1~3분 걸린다
gh api repos/namojo/game-review/pages/builds/latest --jq .status   # built 가 될 때까지
curl -sI https://namojo.github.io/game-review/ | head -1                      # 200
curl -s  https://namojo.github.io/game-review/data/reviews.json | head -c 200 # JSON
  • 기다릴 때 sleep 반복 대신 Monitor 도구의 until 루프나 백그라운드 명령을 쓴다.
  • 재배포: 변경 → git add -A && git commit -m "..." && git push. Pages 가 자동으로 다시 빌드한다.
  • 강제 푸시(--force)는 쓰지 않는다.
  • 배포 뒤 공개 URL에서 Playwright로 첫 화면·인박스·상세를 다시 열어 콘솔 오류가 없는지 확인한다. 로컬에서 되던 것이 하위 경로 때문에 깨지는 경우가 가장 흔하다.

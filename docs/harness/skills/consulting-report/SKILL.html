description썬더게임즈 AI 전환 컨설팅의 과제별 산출물(리뷰 대응 자동화·주간 이벤트 제작 자동화·광고 운영 분석 자동화)을 하나의 통합 보고서(HTML + Markdown)로 엮는 절차. 적용 방안, 구현 가이드, ROI(가정 명시), 로드맵, 거버넌스, 의사결정 요청 사항을 고객사 경영진·실무자가 함께 읽을 수 있게 정리한다. 통합 보고서 작성, 컨설팅 보고서 갱신, 경영진 요약, 로드맵·ROI 수정 요청 시 사용한다. 개별 과제의 상세 산출물 제작에는 쓰지 않는다.

통합 컨설팅 보고서

독자와 목적

  • 1차 독자: 썬더게임즈 대표·운영/디자인/마케팅 리드. "무엇을, 왜, 어떤 순서로, 얼마의 노력으로" 를 15분 안에 판단할 수 있어야 한다.
  • 2차 독자: 실제 구현 담당자. 각 과제의 상세 가이드(Markdown)로 바로 내려갈 수 있어야 한다.

보고서 목차

  1. 요약 (1페이지) — 3개 과제 한 줄 결론, 기대 효과(시간), 바로 결정할 일 3가지
  2. 진단 — 과제별 현재 방식·담당·어려움·소요 시간(고객이 준 원문을 그대로 인용), 데이터로 확인한 사실(리뷰 378건 분석 결과 등)
  3. 과제별 적용 방안 — 각각 같은 틀: AS-IS → TO-BE 흐름, 자동/사람 역할 분담, PoC 결과(링크·이미지), 구현 가이드 요약(기술·단계·기간), 리스크
  4. ROI — references/roi-model.md 방식. 모든 가정값을 표로 드러낸다.
  5. 통합 로드맵 (12주) — 과제 간 공통 기반(Claude API 계정, 비밀 관리, 스케줄러, 메신저 알림)을 먼저 깐다
  6. 거버넌스 — AI 사용 원칙(사람 승인, 공개 게시물 검수, 개인정보, 비용 상한, 로그)
  7. 다음 단계·확인 요청 사항 — [확인 필요]로 표시된 항목을 모은다
  8. 부록 — 데이터 출처, 용어, 하네스 사용법(이 프로젝트의 Claude Code 하네스로 재실행하는 방법)

작성 원칙 — 이유

  • 숫자에는 출처가 있다. 실측(리뷰 수·분포·현재 답변 템플릿 수), 고객 제공(소요 시간), 가정(검수 시간) 세 종류를 표시한다. 섞으면 신뢰를 잃는다.
  • PoC를 보여준다. 리뷰 웹서비스 URL, 실제 리뷰에 대한 "현재 템플릿 답변 vs AI 답변" 비교 3건, 생성한 이벤트 배너 이미지, 광고 일일 리포트 샘플을 본문에 넣는다. 말보다 결과물이 설득한다.
  • 과장하지 않는다. 리뷰 대응은 하루 약 6건 규모라 절감 시간 자체는 크지 않다. 대신 품질(맞춤 답변)·속도(P1 24시간)·인사이트(부서별 전달) 효과가 크다는 점을 정직하게 쓴다.
  • 고객 용어를 쓴다. 고객이 쓴 단계명(리뷰 수집 → 유형 분류 → 번역 → 답변 초안 생성 → 담당자 검수 → 답변 등록)을 그대로 목차와 흐름도에 쓴다.

HTML 형식

  • 단일 파일, 외부 의존 최소(웹 글꼴은 Google Fonts만). 이미지는 상대 경로(../task2-weekly-event/...)로 연결한다.
  • 왼쪽 고정 목차(모바일에서는 상단 접이식), 본문 최대 폭 780px 안팎, 표·흐름도·KPI 카드.
  • 라이트·다크 모드, 인쇄용 CSS(@media print: 목차 숨김, 페이지 나눔).
  • 시각 방향은 frontend-design 스킬로 정한다. 컨설팅 보고서답게 절제하되 게임사 고객에 맞는 따뜻한 포인트 색을 하나 쓴다.

재실행

  • 특정 장만 수정: 해당 장만 고치고 요약(1장)의 수치가 본문과 일치하는지 다시 확인한다.
  • 과제 산출물이 바뀌면: 그 과제 장과 ROI·로드맵을 갱신한다.

description썬더게임즈(T.G Inc) 「원시인 형님들 키우기」 Google Play·App Store 리뷰를 수집하고, 유형 분류·한국어 번역·GM Mr. Bow 페르소나 답변 초안을 만들어 검증하는 운영 절차. 리뷰 수집, 리뷰 분류, 리뷰 번역, 답변 초안 생성, 리뷰 배치 처리, 템플릿 답변 개선, 리뷰 데이터 갱신·재수집·재분류 요청 시 사용한다. 리뷰를 보여주는 웹 화면 구현·배포는 review-web-service, 광고 성과 분석은 ad-performance-automation 스킬이 맡는다.

리뷰 대응 운영 절차

운영팀은 리뷰 1건에 평균 2분을 쓰고, 다른 업무에 밀리면 며칠 치를 몰아서 처리한다. 현재는 별점별 고정 문구 4~5종을 돌려 쓴다(예: 광고 불만에도 "기대에 부응하지 못해 사과드립니다"). 이 절차의 목표는 담당자가 검수만 하면 되는 상태까지 자동으로 만드는 것이다. 수집 → 분류 → 번역 → 초안 → (사람) 검수 → 등록 가운데 검수 앞까지를 맡는다.

전체 흐름

단계 담당 도구 산출물
1. 수집 오케스트레이터 scripts/fetch_reviews.py _workspace/01_collector_reviews_raw.json
2. 사전 분류·배치 오케스트레이터 scripts/make_batches.py _workspace/02_batches/batch_{name}.json, manifest.json
3. 분류·번역·초안 review-ops-analyst (배치당 1명) 이 문서 + references _workspace/03_analyst_drafts_{name}.json
4. 검증 분석가 본인 → 오케스트레이터 scripts/validate_drafts.py 종료 코드 0
5. 병합 오케스트레이터 scripts/merge_for_site.py game-review/data/reviews.json

스크립트는 프로젝트 루트에서 ./.venv/bin/python 으로 실행한다(google-play-scraper·playwright 설치됨). venv 가 없으면 python3 -m venv --system-site-packages .venv && ./.venv/bin/pip install google-play-scraper.

./.venv/bin/python .claude/skills/review-response-ops/scripts/fetch_reviews.py \
  --out _workspace/01_collector_reviews_raw.json --days 60 --max-per-source 200
./.venv/bin/python .claude/skills/review-response-ops/scripts/make_batches.py \
  --raw _workspace/01_collector_reviews_raw.json --outdir _workspace/02_batches

수집 기간은 운영 주기에 맞춘다. 일일 운영은 --days 2, 데모·현황 분석은 --days 60. 작성자 이름은 저장하지 않는다. 공개 사이트에 게시될 수 있기 때문이다.

3단계: 배치 하나를 처리하는 방법 (분석가용)

  1. 배치 파일을 읽는다. style_examples 에 언어별 기존 운영자 답변이 들어 있다. 이 말투와 서명(GM Mr. Bow)을 기준으로 삼는다.
  2. references/taxonomy.md 로 리뷰마다 category·sentiment·priority·route_to·needs_cs·flags 를 정한다.
  3. 실제 언어를 판별해 detected_lang 에 적는다. App Store 는 국가로 언어를 추정했으므로 틀릴 수 있다.
  4. 한국어가 아니면 translation_ko 에 자연스러운 한국어 번역을 쓴다. 운영자가 원문을 몰라도 판단할 수 있어야 한다.
  5. 답변을 쓴다. references/reply-guidelines.md 를 따른다. - route: "template"(짧은 칭찬) → 배치 언어별로 먼저 만든 템플릿 3종 중 하나를 고르고 reply_strategy: "template". 3종을 돌아가며 써서 같은 문구가 연속되지 않게 한다. - route: "llm" → 리뷰 내용을 구체적으로 짚는 맞춤 답변, reply_strategy: "personalized". 사전 분류가 template 이어도 내용상 문제가 보이면 personalized 로 바꾼다.
  6. 한국어가 아니면 reply_ko 에 답변의 한국어 번역을 쓴다. 검수자가 답변 내용을 확인하는 용도다.
  7. 결과 파일을 쓰고 검증한다. 오류가 0이 될 때까지 고친다.
./.venv/bin/python .claude/skills/review-response-ops/scripts/validate_drafts.py \
  --batch _workspace/02_batches/batch_ko-1.json --drafts _workspace/03_analyst_drafts_ko-1.json

출력 형식

{
  "batch": "ko-1",
  "templates": { "ko": ["템플릿1", "템플릿2", "템플릿3"] },
  "drafts": [
    {
      "id": "gp-ko-1a2b3c4d5e",
      "category": "purchase_issue",
      "sentiment": "negative",
      "priority": "P1",
      "route_to": "cs",
      "needs_cs": true,
      "summary_ko": "광고 제거 구매 후 미적용",
      "detected_lang": "ko",
      "translation_ko": null,
      "reply": "안녕하세요, 원시인 형님들 키우기 GM Mr. Bow입니다. ...",
      "reply_ko": null,
      "reply_strategy": "personalized",
      "confidence": 0.9,
      "flags": ["refund_request"]
    }
  ]
}
  • summary_ko 는 30자 안팎의 명사형 요약이다. 대시보드의 이슈 목록에 그대로 쓰인다.
  • confidence 는 분류와 답변이 맞다고 확신하는 정도(0~1)다. 0.6 미만이면 flags 에 needs_human 을 넣는다.
  • 배치에 있는 모든 id 를 정확히 한 번씩 포함한다. 빠지면 화면에 '분석 대기'로 남는다.

품질 기준 — 왜 이렇게 하는가

  • 리뷰 내용을 짚는다: "광고가 3개씩 나온다"에는 광고 빈도에 대한 피드백을 팀에 전달하겠다고 답한다. 일반적인 사과만 하면 사용자는 읽지 않았다고 느끼고, 다른 잠재 사용자도 그렇게 본다. 스토어 답변은 1:1 응대가 아니라 공개 게시물이다.
  • 약속하지 않는다: 날짜, 보상, 기능 추가를 확정하지 않는다. 지키지 못하면 다음 리뷰가 더 나빠진다.
  • 금전·계정 문제는 고객센터로 넘긴다: 공개 답변에서 결제 정보나 계정 정보를 요구하지 않는다. 게임 내 [설정 > 고객센터]로 안내하고, 무엇을 준비하면 빠른지(영수증의 주문번호, 게임 내 UID, 스크린샷)를 알려준다.
  • 글자 수 한도: Google Play 답변은 350자(공백 포함)를 넘으면 API가 거부한다. 목표는 150~300자다.

재실행

  • 새 리뷰만 추가(누적 운영): 기존 사이트 데이터를 기준으로 쌓는다. 덮어쓰면 기존 리뷰와 검수 상태가 사라진다. bash fetch_reviews.py --out _workspace/01_collector_reviews_raw.json --days 2 make_batches.py --raw _workspace/01_collector_reviews_raw.json --outdir _workspace/02_batches \ --exclude-existing game-review/data/reviews.json # 이미 ai 가 있는 id 는 빼고 새 id 만 배치 # (새 배치만 분석) merge_for_site.py --workspace _workspace --out game-review/data/reviews.json \ --base game-review/data/reviews.json --keep-days 180 # id 기준 누적, stats 전체 재계산
  • 특정 배치만 다시: 해당 03_analyst_drafts_{name}.json 을 지우고 그 배치만 분석가에게 맡긴다.
  • 답변 톤 변경 요청: references/reply-guidelines.md 를 먼저 고치고 전 배치를 다시 실행한다. 지침과 결과가 어긋나지 않게 하기 위해서다.

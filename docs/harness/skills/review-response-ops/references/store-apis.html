운영 전환용 공식 API

PoC는 공개 데이터(google-play-scraper, iTunes RSS)로 수집했다. 운영에서는 아래 공식 API로 바꾼다. 출력 스키마(fetch_reviews.py 의 필드)는 그대로 유지해, 그 뒤 단계(분류·초안·웹 화면)를 고치지 않아도 되게 한다.

Google Play — Android Publisher API v3 (Reply to Reviews)

항목 내용
목록 GET https://androidpublisher.googleapis.com/androidpublisher/v3/applications/{packageName}/reviews
답변 POST .../reviews/{reviewId}:reply 본문 {"replyText": "..."} — 기존 답변이 있으면 덮어쓴다
인증 Google Cloud 서비스 계정 → Play Console [사용자 및 권한]에서 해당 앱에 "리뷰 답변" 권한 부여
제약 1 목록은 최근 1주 안에 작성·수정된 리뷰만 준다. 며칠씩 몰아서 처리하면 놓치는 리뷰가 생긴다 → 매일 자동 수집이 필요하다
제약 2 답변은 350자 를 넘으면 거부된다. HTML 태그는 제거된다
제약 3 할당량이 있다. 적용 전에 developers.google.com/android-publisher/quotas 에서 현재 값을 확인하고, 배치 등록 스크립트에 요청 간격을 둔다
패키지 com.primitivebrother.thunder.google

App Store — App Store Connect API

항목 내용
목록 GET /v1/apps/{id}/customerReviews?sort=-createdDate (국가 필터: filter[territory])
답변 POST /v1/customerReviewResponses — data.attributes.responseBody, relationships.review
인증 App Store Connect API 키(.p8) + JWT(ES256). 키 역할은 고객 지원 권한 이상
한도 답변 본문 5,970자. 표시 품질을 위해 Google Play 와 같은 길이를 유지한다
앱 ID 1490207503

권장 운영 구조

[매일 09:00 KST 스케줄러 — GitHub Actions 또는 Cloud Scheduler]
  1. 공식 API로 최근 리뷰 수집 → 기존 DB와 비교해 새 리뷰만 추림
  2. Claude API로 분류·번역·초안 (분류·번역: claude-haiku-4-5, 맞춤 답변: claude-sonnet-5-5)
  3. 결과 저장(DB 또는 JSON) → 웹 검수 화면 갱신
  4. P1(결제·계정) 신규 건은 메신저 알림
[담당자] 웹 화면에서 승인·수정
  5. 승인 건 → 등록 스크립트가 API로 답변 등록 → 상태 '등록 완료'
  • 사람이 승인하기 전에는 자동 등록하지 않는다. 공개 답변은 되돌리기 어렵고 브랜드에 바로 노출되기 때문이다. 운영이 안정되면 P3 템플릿 답변만 자동 등록으로 넓힐 수 있다.
  • API 키·서비스 계정 키는 저장소에 넣지 않는다. GitHub Actions Secrets 나 클라우드 비밀 관리자에 둔다.

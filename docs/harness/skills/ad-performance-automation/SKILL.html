광고 운영·성과 분석 자동화

마케팅 담당자가 매일 1시간 이상 국가·캠페인·소재별 데이터를 직접 확인하고 있다. 목표는 매일 아침 5분 안에 읽고 결정할 수 있는 리포트가 자동으로 도착하고, 담당자는 제안된 액션을 승인·거절하는 데에만 시간을 쓰게 하는 것이다.

guide.md 목차 (이 순서로 쓴다)

  1. 현황 진단 — 지금 1시간이 어디에 쓰이는지 분해(데이터 내려받기·엑셀 정리·비교·보고)하고, 자동화 가능한 부분과 사람이 해야 하는 판단을 나눈다.
  2. 목표 상태와 원칙 — "AI는 제안, 사람은 승인", 데이터 정합성 우선, 단계적 자동화.
  3. KPI 체계 — references/kpi-framework.md 기반. 방치형 RPG의 하이브리드 수익(인앱 결제 + 광고 수익)을 반영한 ROAS 정의.
  4. 데이터 아키텍처 — references/data-integration.md 기반. 소스 → 적재 → 정규화 → 분석 → 리포트·알림. 그림(ASCII 또는 Mermaid)과 표.
  5. 분석 로직 — references/analysis-playbook.md 기반. 이상 탐지, 소재 피로, 예산 재배분 규칙, 안전장치.
  6. AI(Claude)의 역할 — 숫자 계산은 코드가, 해석·우선순위·문장화는 Claude가 맡는 분업. 프롬프트 설계, 환각 방지(숫자는 findings.json 에 있는 값만 인용).
  7. 리포트·알림 설계 — 일간(메신저 5줄 요약 + 상세 링크), 주간(국가·소재 심층), 실시간 알림 조건.
  8. 도입 로드맵 — 3단계(예: 1단계 노코드 커넥터 + 리포트 자동화 → 2단계 BigQuery + 분석 스크립트 + Claude 리포트 → 3단계 승인형 예산 조정 실행). 단계별 기간, 필요 인력·권한, 비용 범위, 완료 기준.
  9. 리스크와 대응 — 어트리뷰션 지연·SKAN, API 권한·토큰 만료, 학습 단계 초기화, 데이터 불일치(매체 vs MMP), 개인정보.
  10. 기대 효과 — 시간 절감(가정값 명시), 의사결정 속도, 낭비 예산 조기 차단. 근거 없는 % 개선 수치를 쓰지 않는다.
  11. 샘플 실행 방법 — sample/ 폴더 실행 명령과 결과 해설.

작업 원칙 — 이유

  • 숫자는 코드가 계산한다. LLM이 표를 보고 직접 계산하면 틀린 숫자가 그럴듯하게 섞인다. analyze_ads.py 가 판정과 수치를 만들고, Claude는 그 결과만 문장으로 바꾼다.
  • 실제 계정 데이터가 없다는 점을 숨기지 않는다. 샘플은 가상 데이터라고 파일 머리말과 리포트 첫 줄에 밝힌다. 썬더게임즈의 실제 매체 구성·MMP·예산은 확인 대상으로 표시한다([확인 필요]).
  • 매체 규칙을 존중한다. Meta·Google은 예산·입찰을 크게 바꾸면 학습 단계가 다시 시작된다. 제안 규칙에 변경 폭 상한과 쿨다운을 넣는다.
  • 최신 사실은 출처를 단다. API 버전, 지표 이름, 정책은 자주 바뀐다. 웹에서 공식 문서를 확인하고 guide.md 끝에 출처 목록을 둔다.
  • 샘플은 실제로 실행해 본다. python3 generate_sample_data.py && python3 analyze_ads.py 가 표준 라이브러리(또는 pandas)만으로 오류 없이 돌아야 한다. 가상 데이터에는 탐지되어야 할 문제(소재 피로, 특정 국가 CPI 급등, 추적 누락 의심)를 일부러 심고, 분석 결과가 그것을 실제로 잡아내는지 확인한다.

재실행

  • 가이드 일부 보완: 해당 절만 고치고 목차·용어 일관성을 확인한다.
  • 실제 데이터 연결 요청: data-integration.md 의 커넥터 절차대로 analyze_ads.py 입력을 바꾼다. 스키마(아래 references 의 표준 컬럼)는 유지한다.

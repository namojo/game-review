매일 돌리는 검사 (순서대로)

# 검사 판정 규칙(초기값 — 4주 운영 후 자사 데이터로 조정) 결과 유형
0 데이터 신선도·완결성 어제 날짜 행이 매체별로 있는가, 지출 > 0인데 설치 = 0인 국가·캠페인이 있는가 data_issue (추적 누락 의심 → 분석보다 먼저 보고)
1 예산 소진 속도 월 예산 대비 누적 지출이 경과일 비율 ±15% 밖 pacing
2 지표 이상 국가×캠페인 CPI·CTR·D0 ROAS가 최근 14일 기준선(중앙값·MAD) 대비 강건 z-score > 3 anomaly
3 소재 피로 같은 소재의 최근 3일 CTR(또는 IPM)이 첫 3일 대비 −25% 이상 + Meta frequency > 3 creative_fatigue
4 우수 소재 같은 캠페인 안에서 IPM 상위 20%이고 표본 충분 scale_creative
5 예산 재배분 아래 규칙 budget_up / budget_down / hold

예산 재배분 규칙

  • 대상: 최근 7일 지출 ≥ 최소 표본(예: $200), 기준 지표는 D7 ROAS(확정분) 또는 D0 ROAS × 과거 D7/D0 배수(추정).
  • 목표 대비 ≥ 120% 이고 CPI 추세가 안정적 → +15~20% 증액 제안
  • 목표 대비 < 70% 이고 3일 연속 → −20% 감액, 2주 지속 시 일시 중지 검토
  • 그 사이 → 유지
  • 변경 폭 상한 20%, 같은 캠페인 쿨다운 3일: 매체 알고리즘이 크게 바뀐 예산·입찰에 다시 학습하는 동안 성과가 흔들리기 때문이다.
  • 월 총예산은 넘기지 않는다. 증액분은 감액분에서 먼저 충당한다(제로섬 재배분이 기본).

안전장치

  • 모든 제안은 confidence(표본 충분 여부)와 reason(규칙 + 수치)을 붙인다.
  • 실행 권한이 있어도 처음 8주는 제안만 한다. 사람이 승인한 비율·결과를 기록해 규칙을 고친다.
  • 데이터 문제(data_issue)가 있으면 그 범위의 예산 제안을 내지 않는다. 잘못된 데이터로 내린 결정이 가장 비싸다.

일일 리포트 형식 (메신저용 5줄 + 상세)

[UA 일일 리포트 | 10/06 | 가상 데이터]
1) 어제 지출 $X(전주 대비 +a%) · 설치 N · CPI $Y · D0 ROAS Z%
2) 🔴 즉시 확인: (가장 심각한 1건 — 데이터 문제 우선)
3) 🟠 소재: (피로 소재 n개, 확장 후보 n개)
4) 💰 예산 제안: (증액 n건 / 감액 n건, 순변동 $)
5) 오늘 할 일: 승인할 제안 링크, 교체할 소재 목록
  • 숫자는 findings.json 에 있는 값만 쓴다. 리포트 프롬프트에 "입력에 없는 숫자를 만들지 말 것"을 명시한다.
  • 심각도 순서: data_issue > 지출 이상 > 성과 급락 > 소재 피로 > 확장 기회.

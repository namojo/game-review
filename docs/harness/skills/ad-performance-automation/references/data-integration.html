데이터 연동

API 버전·필드 이름은 자주 바뀐다. 아래는 설계 기준이며, guide.md 를 쓸 때 공식 문서로 현재 버전을 확인하고 출처를 단다.

소스별 연동

소스 방법 핵심 내용 주의
Meta Marketing API Insights (GET /act_{ad_account_id}/insights) level=ad, time_increment=1, breakdowns=country, fields: spend, impressions, clicks, frequency, actions(mobile_app_install), video 3초 조회 비즈니스 관리자 시스템 사용자 토큰(ads_read)으로 장기 토큰 운영. 대량 기간은 비동기 리포트 작업. 호출 한도(앱·계정 단위)
Google Google Ads API + GAQL (campaign, ad_group, ad_group_ad_asset_view) metrics.cost_micros(÷1e6), impressions, clicks, conversions, conversions_value, segments.date, 국가는 geographic_view/user_location_view 개발자 토큰 + OAuth + MCC login-customer-id. App 캠페인은 소재 단위가 아니라 에셋 단위 성과(성과 라벨)만 제공
MMP AppsFlyer(Pull API·Cohort API) / Adjust(Report Service API) 등 매체 간 동일 기준 설치·코호트 수익·리텐션 설치·ROAS의 기준 원천은 MMP. 매체 자체 보고치와 다르다(어트리뷰션 창·중복 귀속)
iOS SKAdNetwork / AdAttributionKit (MMP 경유) 지연·집계 포스트백 사용자 단위 데이터 없음. iOS 판단은 집계·추정 기반임을 명시
수익 Firebase → BigQuery 내보내기, 광고 미디에이션(AdMob·AppLovin MAX 등) 노출 단위 수익 IAP·광고 수익을 설치 코호트에 붙인다 방치형은 광고 수익을 빠뜨리면 ROAS가 크게 낮게 나온다

썬더게임즈가 실제로 쓰는 MMP·미디에이션·BI는 확인 대상이다([확인 필요]). 확인 전에는 설계를 MMP 중립적으로 쓴다.

적재·처리 구조 (권장)

매일 06:00 KST  ─ 스케줄러(Cloud Scheduler 또는 GitHub Actions)
  ├─ extract_meta.py / extract_google.py / extract_mmp.py  → 원본 테이블(raw_*)
  ├─ transform.sql  → 표준 컬럼 테이블(ads_daily) — kpi-framework.md 의 스키마
  ├─ analyze_ads.py → findings(JSON): 이상 탐지·소재 피로·예산 제안
  ├─ Claude API     → 리포트 문장화(findings 만 입력) → 메신저/메일
  └─ BI 대시보드(Looker Studio 등)는 ads_daily 를 직접 읽는다

단계별 도구 선택

단계 수집 저장 분석·리포트 장점 / 한계
1 노코드 Supermetrics·Funnel 등 커넥터 Google Sheets / BigQuery 시트 수식 + Claude로 요약 2주 안에 시작. 커넥터 비용, 로직 확장 한계
2 코드 파이프라인 직접 API 호출 스크립트 BigQuery analyze_ads.py + Claude API 규칙을 자유롭게 확장, 비용 낮음. 개발·유지보수 필요
3 에이전트 2단계 + MCP 서버(조회 전용으로 시작) 동일 Claude Code/에이전트가 대화형 분석, 승인 후 예산 변경 API 호출 질문형 분석·실행까지. 권한·감사 로그·승인 절차 필수

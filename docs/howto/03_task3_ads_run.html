03. 과제 3 — 광고 운영·성과 분석 실행 방법

지금 있는 것은 가상 데이터로 동작하는 샘플이다. 썬더게임즈의 실제 광고 계정은 아직 연결하지 않았다. 설계 전체는 과제 3 가이드에 있다. 이 문서는 (1) 샘플을 직접 돌려 보는 방법, (2) 실제 데이터를 연결한 뒤 하네스에 요청하는 방법을 다룬다.

원칙은 하나다. 숫자는 코드가 계산하고, Claude는 그 결과(findings.json)만 읽어 문장을 쓴다. 리포트의 숫자는 검증기를 통과해야 발송한다.

1. 샘플 실행 — 5분

Python 3.10 이상, 표준 라이브러리만 쓴다.

cd deliverables/task3-ads-automation/sample
python3 generate_sample_data.py      # [가상 데이터] 1,434행 → ads_daily_sample.csv, budget_config.json
python3 analyze_ads.py               # → findings.json (화면에 요약 출력)
python3 check_report_numbers.py sample_daily_report.md   # 리포트 숫자 검증
python3 test_check_report_numbers.py # 검증기 시험(원본 통과 + 변형 13건 차단)
python3 sweep_seeds.py 30            # 시드 30개 반복 검증
python3 make_report.py --dry-run     # Claude API 에 보낼 요청 확인(키 불필요)
파일 내용
findings.json 판정 결과: summary, findings(F01~), budget_proposals(B01~), checks, near_misses
sample_daily_report.md 5줄 일일 리포트 예시(가상 데이터)
analyze_ads.py 탐지 규칙. 기준값은 RULES 에 모여 있다
budget_config.json 월 예산·일 예산·마지막 변경일·Tier별 목표 ROAS(가상)
report_prompt.md Claude 시스템·사용자 프롬프트

Claude로 리포트를 실제로 쓰게 하는 두 가지 방법

(1) API 키로:

pip install anthropic
export ANTHROPIC_API_KEY=...
python3 make_report.py               # 리포트 생성 → 숫자 검증. 실패하면 종료 코드 2(발송 보류)

(2) API 키 없이 Claude Code에서:

deliverables/task3-ads-automation/sample/findings.json 을 report_prompt.md 규칙대로 5줄 일일 리포트로 써줘. findings.json 에 없는 숫자는 쓰지 말고, 다 쓰면 check_report_numbers.py 로 검증해서 통과한 것만 보여줘.

2. 하네스에 요청하는 프롬프트

샘플·가이드 보완:

과제 3만 다시 — guide.md 의 '오탐 하루 0.33건' 셈 기준을 밝히고 QA D 재계산(9건)과 맞춰줘. 끝나면 QA 트랙 D 재검증.

analyze_ads.py 소재 피로 규칙에 '3초 조회율 20% 이상 하락' 조건을 추가하고, sweep_seeds.py 30 으로 탐지율·오탐이 어떻게 바뀌는지 보여줘.

실제 데이터를 연결한 뒤(3절):

Meta·Google 어제 데이터로 일일 리포트 만들어줘 — 데이터는 BigQuery ads_daily 표(또는 data/ads_daily_YYYYMMDD.csv). analyze_ads.py 로 findings.json 을 만들고, 리포트를 쓴 뒤 check_report_numbers.py 를 통과한 것만 보여줘. 예산 제안은 승인 대기로만.

지난주 UA 주간 리포트 써줘 — 매체·국가 Tier·소재별 CPI·D7 ROAS, 피로 소재와 교체 요청 목록, 다음 주 예산 제안(변경 폭 20% 이내, 같은 캠페인 3일 쿨다운).

메타 iOS 캠페인 설치가 0으로 나오는 게 추적 문제인지 진단해줘 — 지출·클릭·설치·SKAN 포스트백 추이를 비교하고, 확인할 MMP 설정 목록을 줘.

W48 블랙 프라이데이 이벤트(과제 2 캘린더)에 맞춰 UA 소재 변형 3종 아이디어와 집행 타이밍을 제안해줘. 이벤트 키아트(keyart/store/)를 소재로 쓸 수 있는지도 봐줘. '광고 없음'을 약속하는 문구는 빼고.

3. 실제 데이터 연결 순서

가이드 4장·8장 요약이다.

단계 할 일 필요한 것
1. 노코드(2~3주) 커넥터(Supermetrics·Funnel 등)로 Meta·Google·MMP → 시트 또는 BigQuery. 표준 컬럼으로 맞추고, Claude 요약은 처음에 사람이 붙여 넣는다 매체 읽기 권한
2. 코드(4~6주) API 수집 → BigQuery ads_daily → analyze_ads.py → make_report.py → 검증 → 메신저 발송. 스케줄러(Cloud Scheduler 또는 GitHub Actions) Meta 시스템 사용자 토큰(ads_read), Google Ads 개발자 토큰 + OAuth, MMP API 토큰, GCP 프로젝트
3. 승인형 실행(8주 제안 운영 뒤) 승인한 예산 변경만 API로 실행 승인 기록(approvals 표)

analyze_ads.py 는 --data(CSV)와 --config(budget_config.json)만 읽는다. 실데이터를 같은 22개 표준 컬럼으로 맞추면 코드를 바꾸지 않고 돌릴 수 있다.

python3 analyze_ads.py --data /path/ads_daily_20261007.csv --config /path/budget_config.json --out findings.json
# 기준일을 바꾸려면 --as-of 2026-10-06

도입 전에 확인할 플랫폼 변화(2026-10-07 공식 문서 확인): Meta Marketing API v24.0은 2026-10-06에 만료됐다. 7d_view·28d_view 어트리뷰션 값은 2026-01-12부터 나오지 않는다. 레거시 Advantage+ 앱 캠페인은 v25.0부터 만들 수 없다. Google 앱 캠페인은 예산·목표 CPI를 한 번에 20% 넘게 바꾸지 말라고 권장한다.

4. 리포트 검증기 사용

python3 check_report_numbers.py 오늘_리포트.md --findings findings.json   # 생략하면 sample/findings.json 과 대조
echo $?                                                   # 0 = 통과(발송 가능), 1 = 발송 보류
python3 test_check_report_numbers.py                      # 규칙을 고친 뒤 검증기 자체 시험
잡는 것 못 잡는 것(사람이 대조)
입력에 없는 숫자, 단위 혼동, 부호 반전(−35% → +35%), 항목 바꿔치기(KR 지출에 US 값, 제안액 맞바꿈) ID·이름 같은 키가 없는 문장의 바꿔치기, 날짜, 숫자가 아닌 서술 오류(원인 추측, 조치 문구 왜곡)

그래서 처음 8주는 담당자가 리포트를 상세 표와 대조해 검수한다.

5. 매일 자동 실행

/schedule 매일 06:40(KST)에 이 프로젝트에서 "어제 광고 데이터로 일일 리포트 만들어줘 — 검증 통과한 것만 메신저용 5줄로, 실패하면 실패 사유만" 를 실행해줘

예약 실행은 클라우드 환경에서 돈다. 데이터 원천(BigQuery 등) 접근 권한을 그 환경에 줘야 한다. 서버 쪽 정식 운영은 가이드 2단계(Cloud Scheduler + make_report.py)를 따른다.

6. 확인이 필요한 것

실데이터 연결 전에 고객이 알려 줘야 하는 C1~C16(매체, 국가 Tier, 러시아어 사용자 유입원, MMP, 미디에이션, 수익 데이터 위치, 월 예산, 목표 ROAS, 계정 시간대, 메신저, 개발 인력, API 권한, iOS·SKAN, 광고 수익 비중, 소재 제작 체계, 메타 캠페인 구조)은 _workspace/07_strategist_notes.md 에 있다.

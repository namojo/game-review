02. 과제 2 — 주간 이벤트 키트를 매주 만드는 방법

이 문서 하나로 운영 담당자와 디자이너가 매주 이벤트 키트를 만들 수 있다. 준비는 00_setup.md를 먼저 끝낸다(특히 codex 로그인, .venv).

한 주에 하는 일

단계 누가 결과
주제 승인 운영 8주 캘린더에서 이번 주에 만들 이벤트 1건을 고른다
하네스 실행 하네스(기획 → 디자인 → QA) 이벤트 키트 1개: 기획서, 13개 언어 문구, 스토어 시트, 키아트 3장, 배너 39장
검수 운영·디자인 [기획 확인 필요] 답변, 문구·이미지 검수
제출 운영 App Store Connect, Play Console

산출물 위치(이벤트마다 폴더 1개):

deliverables/task2-weekly-event/
├── event_calendar.md                     8주 캘린더(주제·근거·리스크·제출 마감)
└── {event_id}/                           예: 2026-w44-halloween
    ├── event_brief.md                    기획서: 기간(KST·UTC), 미션·보상, ko 공지·푸시, [기획 확인 필요] 목록
    ├── copy.json                         13개 언어 문구 — 배너·공지·푸시·스토어 필드의 단일 원천
    ├── glossary_additions.md             새로 번역한 게임 용어 [인게임 표기 확인]
    ├── store_submission.md               Play·App Store 등록 시트(필드별 글자 수, 제출 이미지 경로, 체크리스트)
    ├── keyart/keyart_{16x9,9x16,1x1}.png 글자 없는 생성 원본

    └── localized/banner_{lang}_{landscape,portrait,square}.png   글자 합성 배너(인게임·SNS 전용)

1. 매주 일정표 — "3주 전 제작" 원칙

이벤트 시작 3주 전 주에 키트를 만든다. 그래야 금요일 제출이 시작 17일 전이 되고, 두 스토어의 사전 노출을 모두 받는다. - App Store 인앱 이벤트: 시작 14일 전부터 게시할 수 있고, 심사 시간이 필요하다. - Google Play: 피처링 요청은 시작 14일 전까지, 프로모션 콘텐츠 승인은 최대 4일이다.

요일 할 일 담당 시간
월 3주 뒤 이벤트 주제 승인(캘린더에서 고르거나 하네스에 새로 요청) 운영 10분
월 하네스 실행: "다음 이벤트 키트 만들어줘" 운영 실행만, 하네스 작업 약 30~60분
화 event_brief.md 8장 [기획 확인 필요] 답변 → 하네스에 반영 요청 기획·운영 30분
수 키아트 검수(직접 열어 보기), 필요하면 1장만 재생성 → 배너 다시 합성 디자인 1~2시간
목 문구 검수(ko, 주력 언어 2~3개), glossary_additions.md 게임 화면 표기 대조 운영 30분
금 App Store 인앱 이벤트 제출(게시일 = 시작 14일 전), Play 프로모션 콘텐츠 제출 + 피처링 요청(시즌 이벤트) 운영 30~40분

예: 11/23(월)에 시작하는 블랙 프라이데이 이벤트는 11/2(월) 주에 만들고 11/6(금)에 제출한다.

3. 사람이 검수할 체크리스트

기획(화요일) - [ ] event_brief.md 8장 [기획 확인 필요]에 모두 답했다(없는 게임 시스템·수치가 들어가지 않았다) - [ ] 기간: KST·UTC, 서버 초기화 기준(전 세계 동시/지역별)이 맞다 - [ ] 보상: 무과금으로 기간 안에 핵심 보상을 받을 수 있다 - [ ] 리뷰 불만과의 연결(예: 광고 시청 미션 없음)이 실제 설계에 들어 있다

문구(목요일) - [ ] ko 공지·푸시: 정보통신망법 표기 — "(광고)", 전송자 명칭, 수신 거부 방법. 21:00~08:00 발송 없음 - [ ] 국가별 추모일·종교일 푸시 금지일(예: ko 10/29 이태원 참사 추모일, br 11/2 Finados) - [ ] 게임 용어가 실제 게임 화면 표기와 같다(glossary_additions.md) - [ ] store_submission.md 글자 수 초과 0건(한도에 딱 맞는 필드는 고치면 다시 센다)

이미지(수요일) - [ ] 키아트에 글자·숫자·로고가 없다 - [ ] 캐릭터 생김새(수염 없는 대머리 형님, 허리옷, 맨발, 몽둥이)와 화풍이 게임과 같다 - [ ] 세 규격의 주요 피사체 색이 같다(공룡 색 등) - [ ] 배너: 글자 잘림, 얼굴 가림 없음(언어마다 몇 장씩 열어 본다. localized/_preview_landscape.png 같은 미리보기가 편하다) - [ ] 스토어에는 keyart/store/ 의 글자 없는 사본만 올린다. 합성 배너는 인게임 공지·SNS 전용이다

제출(금요일) - [ ] App Store 게시일 = 시작 14일 전 이내, 이벤트 기간 31일 이내 - [ ] Play 피처링 요청(분기당 4회 한도 — 캘린더의 쿼터 계획 확인) - [ ] 딥링크를 실기기에서 눌러 봤다 - [ ] 대상 국가: 장애가 있는 국가는 노출을 보류한다(예: ru 접속 장애 해결 확인 전)

4. 직접 실행하는 명령 — 하네스 없이 수동으로

하네스가 내부에서 실행하는 명령과 같다. 프로젝트 루트에서 실행한다. {E} = deliverables/task2-weekly-event/{event_id}.

4.1 키아트 3규격 병렬 생성(codex)

E=deliverables/task2-weekly-event/2026-w45-gear-merge
CODEX_MODEL=gpt-6-sol .claude/skills/weekly-event-production/scripts/gen_keyart.sh \
  "$E/keyart" \
  _workspace/00_input/game_art/shot1.png,_workspace/00_input/game_art/shot2.png \
  "가로형 16:9 ...[화풍][장면][구도][금지]...::keyart_16x9.png" \
  "세로형 9:16 ...::keyart_9x16.png" \
  "정사각형 1:1 ...::keyart_1x1.png"
  • 사용법: gen_keyart.sh <out_dir> <참고이미지1,참고이미지2|-> "프롬프트::파일명" ... (최대 5장 동시)
  • 프롬프트 틀은 .claude/skills/weekly-event-production/references/keyart-prompting.md, 실제로 쓴 전문은 지난 키트의 keyart/prompts.md(예: 2026-w44-halloween/keyart/prompts.md)를 복사해 [장면]만 바꾸면 된다.
  • 결과 판정: [ok] keyart_16x9.png … 또는 [fail] …. 로그는 $E/keyart/.codex-logs/<파일명>.stdout.
  • 한 장만 다시 만들려면 그 규격의 "프롬프트::파일명" 하나만 넘긴다.

4.2 스토어 제출용 규격 사본

생성 원본은 1536×1024(3:2)·1024×1536·1254×1254라서 스토어 규격과 다르다. 가운데 기준으로 잘라 규격 사본을 만든다.

7. 매주 자동으로 시작하기

7.1 Claude Code 예약 실행(루틴) — /schedule

/schedule 매주 월요일 09:00(KST)에 이 프로젝트에서 "3주 뒤 시작하는 이벤트 키트 만들어줘 — event_calendar.md 기준, 키아트·배너는 빼고 기획서·copy.json·스토어 시트까지만. [기획 확인 필요] 목록을 마지막에 정리" 를 실행해줘
  • 루틴은 클라우드 환경에서 돈다. 그래서 이 PC의 codex 로그인과 .venv 를 쓸 수 없다. 저장소에 접근할 수 있게 설정해야 한다.
  • 권장 분담: 루틴은 글 작업(캘린더·기획서·copy.json·스토어 시트)을 맡는다. 이미지(키아트·배너)는 수요일에 담당 PC에서 "키아트와 배너만 만들어줘"로 실행한다.
  • 만든 루틴은 /schedule 에서 목록 확인, 일시 중지, 삭제를 할 수 있다.

7.2 담당 PC에서 비대화형 실행(선택)

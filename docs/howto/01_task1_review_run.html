01. 과제 1 — 리뷰 대응을 매일·매주 실행하는 방법

준비는 00_setup.md를 먼저 끝낸다(.venv, gh 로그인). 운영 전환(실제 스토어 등록)의 전체 절차는 과제 1 구현 가이드 6장에 있다.

무엇 어디
검수 웹서비스 https://namojo.github.io/game-review/ (저장소 game-review/)
리뷰 데이터 game-review/data/reviews.json — 매일 누적된다(기존 리뷰·분석 유지, 새 리뷰만 추가)
수집·검증·병합 스크립트 .claude/skills/review-response-ops/scripts/ (사본: game-review/pipeline/)
분류 기준·답변 지침 .claude/skills/review-response-ops/references/taxonomy.md, reply-guidelines.md

두 가지 실행 방법이 있다.

방법 초안을 누가 쓰나 필요한 것 언제
A. 하네스(Claude Code) Claude Code 에이전트(구독 계정) API 키 불필요 지금 규모(하루 약 6건). 권장
B. 파이프라인 스크립트 draft_replies.py 가 Claude API 호출 ANTHROPIC_API_KEY GitHub Actions·서버에서 자동으로 돌릴 때

1. 매일 — 하네스로 갱신(A안)

리뷰 데이터 갱신해줘
하네스가 하는 일 결과
최근 리뷰를 수집하고, 이미 분석했고 내용이 그대로인 리뷰는 뺀다 _workspace/01_collector_reviews_raw.json, _workspace/02_batches/
새 리뷰만 언어 배치로 나눠 분석 에이전트(review-ops-analyst)를 병렬로 돌린다: 분류·번역·답변 초안 _workspace/03_analyst_drafts_*.json
검증(id·스키마·Play 350자·답변 언어) → 누적 병합 game-review/data/reviews.json
웹서비스에 커밋·푸시(GitHub Pages가 자동 재빌드) 공개 URL 갱신

자주 쓰는 변형:

리뷰 데이터 갱신해줘 — 최근 3일치, 배포는 하지 말고 로컬에서만 확인할게.

어제 들어온 P1 리뷰만 요약해줘. 부서(고객센터·개발·BM·기획)별로 나누고, 같은 증상이 몰린 게 있으면 알려줘.

이번 주 부서별 전달 목록을 회의 자료로 만들어줘 — 유형별 건수, 대표 원문 3건씩, 지난주 대비 변화.

gp-ko-5237482aa9 답변 초안을 다시 써줘 — 결제 영수증 주문번호(GPA.)와 UID를 고객센터로 받는 안내는 유지하고, 더 짧게.

2. 직접 실행하는 명령(하네스가 내부에서 쓰는 것과 같다)

프로젝트 루트에서 실행한다.

# 1) 수집 — 최근 2일, 소스당 최대 200건
./.venv/bin/python .claude/skills/review-response-ops/scripts/fetch_reviews.py \
  --out _workspace/01_collector_reviews_raw.json --days 2 --max-per-source 200

# 2) 배치 — 이미 분석했고 내용(text·title·rating)이 그대로인 리뷰는 뺀다
./.venv/bin/python .claude/skills/review-response-ops/scripts/make_batches.py \
  --raw _workspace/01_collector_reviews_raw.json --outdir _workspace/02_batches \
  --exclude-existing game-review/data/reviews.json

# 3) 분석 — Claude Code에 "02_batches 의 배치를 review-ops-analyst 로 분석해줘"

# 4) 검증 — 오류가 있으면 종료 코드 1
./.venv/bin/python .claude/skills/review-response-ops/scripts/validate_drafts.py --all _workspace

# 5) 누적 병합 — 기존 리뷰·분석 유지, 새 id 추가, 180일 보존
./.venv/bin/python .claude/skills/review-response-ops/scripts/merge_for_site.py \
  --workspace _workspace --base game-review/data/reviews.json \
  --out game-review/data/reviews.json --keep-days 180

B안: API 키로 한 번에 돌리기(game-review/pipeline/README.md 와 같다)

cd game-review
export ANTHROPIC_API_KEY=...            # 저장소·코드에 넣지 않는다
python pipeline/fetch_reviews.py --out work/01_collector_reviews_raw.json --days 2 --max-per-source 200
python pipeline/make_batches.py --raw work/01_collector_reviews_raw.json --outdir work/02_batches --exclude-existing data/reviews.json
python pipeline/draft_replies.py --manifest work/02_batches/manifest.json --outdir work --existing data/reviews.json
python pipeline/validate_drafts.py --all work
python pipeline/merge_for_site.py --workspace work --base data/reviews.json --out data/reviews.json --keep-days 180
  • --dry-run 을 draft_replies.py 에 붙이면 호출 수만 보여 준다. --limit 5 로 배치마다 5건만 시험할 수 있다.
  • GitHub Actions: .github/workflows/refresh-reviews.yml 이 1~5단계를 돈다. 저장소 Secrets에 ANTHROPIC_API_KEY 를 넣고 Actions 탭에서 수동 실행한다. 매일 09:00(KST)는 schedule 주석을 풀면 된다.

3. 검수 화면에서 하는 일(매일 10~15분)

  1. 대시보드: 한 줄 요약과 부서별 전달 목록을 본다. 몰림 경고(예: "러시아어 P1 14건이 몰렸습니다")가 있으면 링크를 눌러 해당 리뷰만 연다.
  2. 검수 인박스: 맨 위가 P1이다. 읽고 고친 뒤 승인(A), 판단이 필요하면 보류(H). J/K 로 이동한다.
  3. 결제·계정 P1은 같은 날 고객센터로 넘긴다("회의용으로 복사").
  4. P3 칭찬 템플릿은 일괄 승인한다(실행 취소 가능).
  5. "승인 답변 N건 JSON" 을 내려받는다.

승인 버튼은 이 브라우저에 저장만 한다. 스토어에는 올라가지 않는다. 등록은 4절이다.

4. 승인 답변 등록

cd game-review
python pipeline/post_replies.py approved_replies_YYYYMMDDHHMM.json            # 미리 보기: 등록 대상·제외 사유
export GOOGLE_APPLICATION_CREDENTIALS=/secure/play-service-account.json      # Play: 서비스 계정 + '리뷰 답변' 권한
export ASC_KEY_ID=... ASC_ISSUER_ID=... ASC_PRIVATE_KEY_PATH=/secure/AuthKey.p8  # App Store Connect API 키
python pipeline/post_replies.py approved_replies_YYYYMMDDHHMM.json --execute  # 실제 등록 → posted_replies.jsonl
  • 첫 등록은 5건 이하로 시험하고, 스토어 화면에서 표시 명의·줄바꿈을 확인한다.
  • PoC 데이터의 App Store 리뷰 ID는 RSS 값이다. ASC 리뷰 ID와 같다는 보장이 없으므로, 운영에서는 ASC API로 다시 수집한 ID를 쓴다.

5. 웹서비스 배포 갱신

하네스에 요청한다.

리뷰 웹서비스 재배포해줘 — 공개 전 점검(비밀 키 검사) 하고 푸시해줘.

직접 할 때:

cd game-review
git grep -nE "sk-ant-[A-Za-z0-9_-]{20,}|BEGIN PRIVATE KEY|\"private_key\"\s*:" ; echo "exit=$? (1이면 깨끗)"
git add -A && git commit -m "data: reviews $(date +%F)" && git push
gh api repos/namojo/game-review/pages/builds/latest --jq .status   # built 확인
curl -sI https://namojo.github.io/game-review/ | head -1             # 200

화면을 고치고 싶을 때:

검수 인박스에 '운영 담당(커뮤니티)' 필터를 추가해줘. 로컬에서 390px 까지 확인하고, 배포는 내가 확인한 뒤에.

6. 매주

지난 7일 리뷰 주간 요약 만들어줘 — 평균 별점 추이, 유형별 건수 변화, P1 처리 현황(미답변 남은 것), 부서별 전달 목록.

템플릿 답변 세트를 점검해줘 — 언어별로 지금 쓰는 템플릿과 사용 횟수를 보여 주고, 운영자가 승인할 고정 세트 후보 5종씩 제안해줘.

7. 운영 전환 단계 요약

자세한 내용은 과제 1 구현 가이드 6장에 있다.

  1. 자격 증명 발급: Play 서비스 계정('리뷰 답변' 권한), App Store Connect API 키(.p8·Key ID·Issuer ID)
  2. 운영 방식 결정: A안(검수 화면을 claude.ai Artifact로 + Claude Code 예약 실행) 또는 B안(Vertex AI의 Claude + GCP 백엔드)
  3. 수집을 공식 API로 교체(Play reviews.list 는 최근 1주만 준다 → 매일 실행)
  4. 템플릿 고정 세트 승인
  5. 첫 등록 5건 시험 → 매일 09:00 스케줄 켜기

매일 자동 시작(A안):

/schedule 매일 09:00(KST)에 이 프로젝트에서 "리뷰 데이터 갱신해줘 — 끝나면 새 P1 목록과 부서별 건수만 보고" 를 실행해줘

예약 실행은 클라우드 환경에서 돈다. 저장소 접근과 배포 권한(gh)이 그 환경에 있어야 한다. 없으면 담당 PC에서 claude -p "리뷰 데이터 갱신해줘" 를 예약 작업으로 돌린다(02_task2_weekly_event_run.md 7.2절과 같은 방식).

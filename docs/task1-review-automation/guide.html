  • 작성: 2026-10-07 · consulting-report-editor
  • PoC 검수 화면: https://namojo.github.io/game-review/ · 저장소: https://github.com/namojo/game-review
  • 숫자 표시: [실측] 이 프로젝트에서 데이터로 확인 · [고객] 고객이 준 값 · [가정] 컨설턴트 가정(근거를 함께 적음)
  • 원천: game-review/data/reviews.json(sha1 84969823…, 동결본), game-review/README.md·pipeline/README.md, _workspace/04_engineer_build_notes.md, QA 08_qa_A_report.md·08_qa_B_report.md

한 장 요약

  • 지금: 담당자가 리뷰를 직접 읽고 번역한 뒤 미리 써 둔 답변을 고른다. 건당 2분이다[고객]. 다른 업무에 밀려 며칠 치를 몰아서 처리한다[고객]. 데이터도 같은 모습이다. 최근 60일 운영 답변 343건은 13일에만 등록됐고(9/27 하루 75건), 리뷰가 올라온 뒤 답변까지 중앙값 3.3일(답변 뒤 리뷰를 고친 10건 제외)이 걸렸다[실측]. 답변 문구는 50종이고 상위 5종이 36%다[실측].
  • 바꾸는 것: 고객이 정한 순서 그대로 간다. 리뷰 수집 → 유형 분류 → 번역 → 답변 초안 생성은 매일 자동으로 돌리고, 담당자 검수 → 답변 등록만 사람이 한다. 사람은 P1(돈·계정·진행 불가)부터 읽고, 고치고, 승인한다.
  • PoC로 확인한 것: 공개 리뷰 378건(60일, 하루 약 6.3건, 13개 언어·스토어×언어 16개 조합)을 분류·번역하고 답변 초안을 만들었다. 검수 화면은 공개 URL에서 동작한다(QA 시나리오 33/34·13/13·6/6 통과, 콘솔 오류 0)[실측]. 사람이 먼저 봐야 할 P1 30건, 고객센터로 넘길 18건, 아직 스토어 답변이 없는 결제 P1 1건(1만원 결제 후 0원 표시)을 찾았다[실측].
  • 효과는 시간보다 품질과 속도에서 난다. 하루 6.3건 규모라 연간 절감은 약 62시간(현재 약 77시간 → 약 15시간)이다[실측×고객×가정]. 효과가 큰 쪽은 따로 있다. 광고 불만과 결제 오류에 같은 사과문이 나가던 것이 리뷰마다 맞춤 답변이 된다. P1은 24시간 안에 처리할 수 있다. 러시아어 접속 장애 14건처럼 몰려 있는 문제는 개발팀에 바로 전달된다.
  • 다음 주에 할 일: ① 고객사 자격 증명 2종(Play 서비스 계정, App Store Connect API 키)을 발급한다. ② 미답변 결제 P1을 오늘 처리한다. ③ 러시아어 접속 장애(3.63 버전 서버 버전 확인 무한 로딩)를 개발팀에 넘긴다. ④ 운영 방식(아래 6.3절 A안 또는 B안)을 정한다.

6.1 승인 버튼과 실제 등록은 다르다

  • 검수 화면의 승인 버튼은 이 브라우저에 승인 상태를 저장할 뿐이다. 스토어에는 아무것도 올라가지 않는다.
  • 실제 등록은 승인 답변 JSON을 받아 post_replies.py --execute 로 실행한다. 고객사 자격 증명이 필요하다.
스토어 필요한 자격 증명 발급하는 곳

  • 답변 표시 명의. Play에서는 개발자 이름 'T.G Inc'로 보인다. App Store 조회 결과는 개발자 'T.G', 판매자 'Thundergames'이고, 답변 표시 명의는 App Store Connect에서 확인해야 한다(확인 요청 B-10). 'GM Mr. Bow'는 답변 본문의 서명이다.

6.4 템플릿은 운영자가 승인한 고정 세트로 관리한다

  • 지금 파이프라인은 실행할 때마다 언어별 템플릿을 새로 만들고, 언어별로 최신 6종만 남긴다. 그래서 매일 돌리면 분석가가 다듬은 초기 템플릿이 자동 생성 템플릿으로 차례로 밀려난다(QA A P-7 참고).
  • 권고: 운영자가 승인한 언어별 템플릿 세트(예: 언어마다 5~6종)를 파일로 고정한다. 파이프라인은 그 세트에서 골라 쓰기만 하고 새로 만들지 않는다. 세트는 분기마다 검토한다.
